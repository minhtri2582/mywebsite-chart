#### 1. What is a VPC in AWS?

Answer: A VPC (Virtual Private Cloud) is a logically isolated section of the AWS Cloud where you can launch AWS 
resources in a virtual network that you define. It allows control over IP address ranges, subnets, route tables, internet gateways, NAT gateways, and more. VPC helps create a secure and customizable network environment in the cloud.

⸻

#### 2. What is the difference between Public and Private Subnets in a VPC?

Answer:

- A public subnet is associated with a route table that has a route to the Internet Gateway (IGW), enabling resources (like EC2 instances) to communicate with the internet.

- A private subnet does not have a route to the IGW, so resources inside it cannot reach the internet directly.

You usually place web servers in public subnets and databases or backend services in private subnets for security.

⸻

#### 3. What is a Route Table and how does it work?

Answer: A route table contains a set of rules (routes) that determine where network traffic is directed. Each subnet 
in a VPC must be associated with a route table. The main route table is associated by default, but you can create and associate custom ones.

Example routes:

- 0.0.0.0/0 → IGW for public access

- 0.0.0.0/0 → NAT Gateway for outbound-only internet access from private subnets

⸻

#### 4. What is a NAT Gateway, and why is it used?

Answer: A NAT (Network Address Translation) Gateway allows instances in a private subnet to access the internet (for 
updates, APIs, etc.) without exposing them to inbound internet traffic.

You typically:

- Place NAT Gateway in a public subnet

- Route private subnet traffic to the NAT Gateway

⸻

#### 5. What is a VPC Endpoint?

Answer:A VPC Endpoint enables private connections between your VPC and AWS services without needing an internet gateway, NAT device, VPN, or AWS Direct Connect.

	- More secure (no exposure to public internet)
	- Reliable & faster (private AWS backbone network)
	- Cost-saving (no NAT Gateway / Internet Gateway data processing charges for that traffic)

There are two types:
1.	Interface Endpoints (powered by AWS PrivateLink):

- Create an elastic network interface (ENI) with a private IP in your subnet.

- Used for services like S3, DynamoDB, SNS, SQS, Secrets Manager, KMS, etc.


VPC ↔ ENI (private IP) ↔ AWS Service

2.	Gateway Endpoints

- Add a route in your route table pointing to the gateway endpoint.

- Only supports S3 and DynamoDB.

- Cheaper (free to use) compared to interface endpoints.

⸻

#### 6. What is the difference between VPC Peering and a VPN Connection?

Answer:

🔹 VPC Peering

- Definition: A private network connection between two VPCs (in same or different AWS accounts/regions).

- Traffic Path: Uses AWS backbone network (never goes over the public internet).

- Security: Very secure; traffic is private and encrypted by AWS infrastructure (no need for VPN).

- Performance: Low latency, high bandwidth (limited only by instance bandwidth).

- Use Cases:

- Communication between VPCs in the same organization.
- Multi-VPC architectures (prod/staging/dev).

⚠️ Limitation: No transitive routing (VPC A ↔ VPC B ↔ VPC C does NOT work).

🔹 VPN Connection (Site-to-Site VPN)

- Definition: An encrypted IPsec tunnel over the public internet between your on-premises network (or another VPC via 
customer gateway) and AWS VPC.
- Traffic Path: Goes through the public internet, but traffic is encrypted.
- Security: Encrypted tunnel (IPsec).
- Performance: Latency and bandwidth depend on the internet connection (less predictable).
- Use Cases:
  - Connect on-premises data center to AWS.
  - Backup connection for AWS Direct Connect.

⸻

📊 Quick Comparison Table

| Feature            | VPC Peering                          | VPN Connection                                   |
|--------------------|---------------------------------------|-------------------------------------------------|
| **Scope**          | AWS VPC ↔ AWS VPC                    | On-premises ↔ AWS VPC (or VPC ↔ VPC via internet) |
| **Traffic path**   | AWS private backbone                 | Public internet (encrypted tunnel)               |
| **Security**       | Private by design                    | Encrypted with IPsec                             |
| **Performance**    | High bandwidth, low latency          | Limited, depends on internet                     |
| **Cost**           | Data transfer costs apply            | VPN hourly + data transfer costs                 |
| **Use cases**      | Multi-VPC communication              | Hybrid cloud, on-prem connectivity               |
| **Transitive routing** | ❌ Not supported                 | ✅ Possible with routing + VPN hub                |

#### 7. What are the different types of Load Balancers in AWS?

Answer:

AWS offers three main types of Elastic Load Balancers:
1.	Application Load Balancer (ALB)
- Works at Layer 7 (HTTP/HTTPS)
- Supports host-based or path-based routing
- Ideal for web apps and containerized services (e.g., ECS, EKS)
2.	Network Load Balancer (NLB)
- Operates at Layer 4 (TCP/UDP)
- Designed for high performance and low latency
- Ideal for real-time or network-intensive apps
3.	Classic Load Balancer (CLB)
- Legacy option (deprecated for most use cases)
- Operates at both Layer 4 & 7, but lacks advanced features of ALB/NLB

⸻

#### 8. When would you use an NLB over an ALB?

Answer: 

Use an NLB when you need:
- TCP/UDP protocol support
- Extreme performance with ultra-low latency
- Static IP addresses
- TLS offloading at the load balancer level

Use ALB when you need:
- Advanced routing (e.g., path/host based)
- HTTP headers inspection
- WebSocket support

⸻

#### 9. What are some best practices when designing VPC architecture?

Answer:
- Split subnets by function (web, app, DB) and tier (public/private)
- Use multi-AZ deployments for HA
- Restrict traffic using NACLs and Security Groups
- Use VPC Flow Logs to monitor traffic
- Minimize public IP usage
- Route private subnets through NAT Gateway, not IGW

⸻

#### 10. Can two VPCs in different regions communicate?

Answer:
Yes, but not via VPC Peering alone. You need:
- Transit Gateway with inter-region peering
- Or use VPN connections
- Or AWS PrivateLink depending on the use case
