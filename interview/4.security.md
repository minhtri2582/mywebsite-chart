🧑‍💼 Interviewer:
Can you explain what AWS IAM is and why we use it?

🧑‍💻 Candidate (You):
Sure. AWS Identity and Access Management (IAM) enables fine-grained access control to AWS resources. It allows creating users, groups, and roles, each associated with policies written in JSON that define what actions are allowed or denied.

Key points:
- Users: People or systems with long-term credentials
- Roles: Used for temporary access, often assumed by services (like EC2 or Lambda)
- Policies: Grant permission to perform actions on resources (e.g., s3:PutObject)

IAM also supports MFA, policy versioning, and permission boundaries for enhanced security.

🧑‍💼 Interviewer:
What’s the difference between AWS Secrets Manager and SSM Parameter Store?

🧑‍💻 Candidate:
Both are used to manage secrets, but they serve slightly different use cases:
- AWS Secrets Manager:
  - Built for storing secrets, credentials, API keys
  - Supports automatic secret rotation with Lambda integration
  - Versioned, encrypted with KMS
  - More expensive but feature-rich
- SSM Parameter Store:
  - Supports plaintext and encrypted parameters
  - Cheaper (free tier available)
  - Good for configuration values and small-scale secret use
  - Lacks native rotation (can be scripted)

Use Secrets Manager for high-security secrets with rotation, and SSM for general configs or non-sensitive values.

🧑‍💼 Interviewer:
How does AWS KMS work and where have you used it?

🧑‍💻 Candidate:
AWS KMS (Key Management Service) allows you to create and manage cryptographic keys. It integrates with most AWS services (e.g., S3, EBS, RDS, Secrets Manager) for encryption at rest.

There are two types of keys:
- AWS-managed keys (e.g., aws/s3)
- Customer-managed CMKs for custom control (rotation, access policies)

I’ve used KMS to:
- Encrypt S3 buckets and EBS volumes
- Encrypt Secrets in Secrets Manager
- Manage envelope encryption for sensitive app data

🧑‍💼 Interviewer:
Explain the difference between NACL and Security Groups in AWS.

🧑‍💻 Candidate:
- Security Groups (SG):
  - Stateful: Responses are automatically allowed
  - Attached to ENIs (EC2, ELB, etc.)
  - Allow-only rules (no deny)
  - Ideal for instance-level control
- Network ACLs (NACL):
  - Stateless: You must explicitly allow return traffic
  - Attached to subnets
  - Allow and deny rules
  - Good for subnet-level filtering (like a firewall)

In most cases, Security Groups are used more frequently, and NACLs are used for additional filtering or subnet-wide policies.

🧑‍💼 Interviewer:
What’s the difference between a stateful and stateless firewall?

🧑‍💻 Candidate:
- Stateful firewall tracks the state of connections (TCP handshakes, etc.). If an incoming packet is part of an established connection, it’s allowed automatically. Example: AWS Security Groups.
- Stateless firewall examines each packet independently. You need rules for both inbound and outbound directions. Example: NACLs, Azure NSGs.

Stateful firewalls are better for application-layer logic and performance.

🧑‍💼 Interviewer:
How would you implement secret rotation securely?

🧑‍💻 Candidate:
Best practices for secret rotation:
1.	Use AWS Secrets Manager or Azure Key Vault with built-in rotation
2.	Set rotation interval (e.g., 30 days)
3.	Implement a Lambda/Azure Function to:
- Generate new secret
- Update in the service (e.g., DB, API)
- Test and mark new version as current
4.	Notify/automate redeploy of dependent services

Also, avoid secrets in source code and monitor for rotation failures.

🧑‍💼 Interviewer:
What does AWS WAF do, and how is it used?

🧑‍💻 Candidate:
AWS WAF (Web Application Firewall) protects applications against web exploits like SQL injection, XSS, etc.
- Integrated with services like CloudFront, ALB, API Gateway
- You define rules or use Managed Rule Sets from AWS or third parties
- You can block/allow/count requests based on IPs, user-agents, URI, or geolocation

I’ve used WAF to block bad bots, restrict countries, and protect APIs from OWASP Top 10 threats.

🧑‍💼 Interviewer:
How do you use CloudTrail for security monitoring?

🧑‍💻 Candidate:
AWS CloudTrail logs API calls made in the AWS environment — including actions from console, SDK, and CLI.

I use it to:
- Detect unusual activities (e.g., login from unknown IP, deleting critical resources)
- Set up event triggers (via EventBridge or Lambda) to notify Slack or email
- Investigate security incidents with timestamps, user, and IP info

CloudTrail logs are often sent to S3 and analyzed via Athena or fed into CloudWatch/SIEM for real-time alerting.

🧑‍💼 Interviewer:
How does Azure Key Vault compare to AWS Secrets Manager?

🧑‍💻 Candidate:
Both are secure vault services for storing secrets and keys. Comparison:

Feature	AWS Secrets Manager	Azure Key Vault
Native Secret Rotation	Yes (Lambda-based)	Yes (for some services)
Certificate Mgmt	Via ACM	Integrated
API/CLI Support	Strong	Strong
Cost	Higher	Slightly cheaper
Identity Integration	IAM + Resource Policies	Azure AD + RBAC

In Azure, I also use Managed Identities to allow VMs, functions, and apps to fetch secrets without hardcoded credentials.
