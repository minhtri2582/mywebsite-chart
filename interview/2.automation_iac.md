🔧 Terraform

1. What is Terraform and how does it work?

Answer:
Terraform is an open-source Infrastructure as Code (IaC) tool developed by HashiCorp. It allows you to define cloud infrastructure (like AWS, Azure, GCP resources) using declarative .tf configuration files. Terraform follows a workflow of:
1.	terraform init – initialize working directory
2.	terraform plan – preview changes
3.	terraform apply – apply changes
4.	terraform destroy – delete resources

It maintains state using a terraform.tfstate file to track the current infrastructure.

⸻

2. What are Terraform providers and modules?

Answer:
•	Provider: A plugin that allows Terraform to interact with APIs (e.g., AWS, Azure, Kubernetes).
•	Module: A reusable container of Terraform configurations. It can represent a single resource or a full environment setup (e.g., VPC + EC2 + S3).

Using modules promotes code reuse and standardization.

⸻

3. How does Terraform manage state? What are the risks and solutions?

Answer:
Terraform uses a state file (terraform.tfstate) to map resources in the real world to the configuration. Risks include:
•	State corruption if multiple users edit it simultaneously
•	Sensitive data exposure (e.g., passwords, secrets)

Solutions:
•	Store state in remote backends (e.g., S3 with DynamoDB for state locking)
•	Enable encryption and versioning
•	Use terraform workspace for environment separation

⸻

4. What’s the difference between terraform plan and terraform apply?

Answer:
•	terraform plan: Shows what changes will occur without actually making them (a dry-run).
•	terraform apply: Executes the planned changes and updates the infrastructure.

plan is useful for reviewing changes before applying them in production.

⸻

5. How do you handle secrets in Terraform?

Answer:
•	Avoid hardcoding secrets in .tf files.
•	Use environment variables, Terraform Cloud Variables, or external secret managers (e.g., AWS Secrets Manager, Vault).
•	Use sensitive = true to suppress output display of secrets.
•	Encrypt state files, especially when stored remotely.

🧪 Jenkins Pipeline

6. What is a Jenkins Pipeline?

Answer:
A Jenkins Pipeline is a suite of plugins that supports implementing and integrating Continuous Integration (CI) and Continuous Delivery (CD) workflows using code (Pipeline as Code).

There are two types:
•	Declarative Pipeline (preferred): Easier to read and structured
•	Scripted Pipeline: More flexible, written in Groovy

⸻

7. What is the structure of a Declarative Jenkinsfile?

Answer:
A basic example:

pipeline {
agent any
stages {
stage('Build') {
steps {
echo 'Building...'
}
}
stage('Test') {
steps {
echo 'Testing...'
}
}
stage('Deploy') {
steps {
echo 'Deploying...'
}
}
}
}


⸻

8. How do you pass parameters to a Jenkins Pipeline?

Answer:
You can define parameters at the top of a Jenkinsfile:

parameters {
string(name: 'ENV', defaultValue: 'dev', description: 'Environment name')
}

Use the parameter in steps:

steps {
echo "Deploying to ${params.ENV}"
}

10. How do you integrate Terraform in a Jenkins Pipeline?

Answer:
You can use Terraform CLI in Jenkins by:
1.	Installing Terraform on the Jenkins agent
2.	Writing pipeline steps to run commands:

pipeline {
agent any
stages {
stage('Terraform Init') {
steps {
sh 'terraform init'
}
}
stage('Terraform Plan') {
steps {
sh 'terraform plan -out=tfplan'
}
}
stage('Terraform Apply') {
steps {
input "Apply changes?"
sh 'terraform apply tfplan'
}
}
}
}

You can also use credentials binding for secret keys.
