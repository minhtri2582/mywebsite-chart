# Greedy Algorithms - Ôn luyện Brown Belt

Nhóm bài "Greedy Algorithms" tập trung vào:
1. **Greedy Strategy** - Chọn lựa tối ưu cục bộ tại mỗi bước
2. **Interval Scheduling** - Sắp xếp và chọn đoạn không giao nhau
3. **Ứng dụng** - Các bài toán tối ưu với điều kiện đơn giản

**Kiến thức cần nhớ:**
- Greedy: Chọn tốt nhất tại mỗi bước, không quay lại
- Điều kiện: Optimal substructure + Greedy choice property
- Độ phức tạp: Thường O(n log n) do sắp xếp, hoặc O(n) nếu đã sắp xếp

## 📚 Giới thiệu: Greedy Algorithms (Thuật toán Tham lam)

### Ý tưởng cơ bản

Greedy algorithm giải quyết bài toán tối ưu bằng cách:
1. **Chọn lựa tối ưu cục bộ** tại mỗi bước
2. **Không quay lại** (không xem xét lại các lựa chọn trước)
3. Hy vọng rằng chuỗi lựa chọn cục bộ sẽ dẫn đến **tối ưu toàn cục**

**Ví dụ:** Bài toán đổi tiền (Coin Change với mệnh giá đặc biệt)

```
Coins: [1, 5, 10, 25], Amount: 67
Greedy: Chọn đồng xu lớn nhất có thể
67 = 25 + 25 + 10 + 5 + 1 + 1 → 6 đồng xu ✅
```

**Lưu ý:** Greedy không luôn đúng! Với coins = [1, 3, 4], amount = 6:
- Greedy: 4 + 1 + 1 = 6 (3 đồng) ❌
- Optimal: 3 + 3 = 6 (2 đồng) ✅

### Khi nào dùng Greedy?

1. **Greedy Choice Property:**
   - Lựa chọn tối ưu cục bộ là một phần của lời giải tối ưu toàn cục
   - Không cần xem xét lại các lựa chọn trước

2. **Optimal Substructure:**
   - Lời giải tối ưu của bài toán con là một phần của lời giải tối ưu bài toán lớn

3. **Dấu hiệu nhận biết:**
   - Bài toán yêu cầu tối đa/tối thiểu số lượng
   - Có thể sắp xếp để chọn theo thứ tự
   - Không cần backtracking

### So sánh với các phương pháp khác

| Phương pháp | Đảm bảo tối ưu? | Độ phức tạp | Khi nào dùng |
|-------------|-----------------|-------------|--------------|
| **Greedy** | ❌ Không luôn | O(n log n) | Khi chứng minh được tính đúng |
| **DP** | ✅ Có | O(n²) hoặc cao hơn | Khi cần xét tất cả khả năng |
| **Brute Force** | ✅ Có | O(2^n) | Khi không có cách nào khác |

### Template cơ bản

```python
def greedy_solution(data):
    # Bước 1: Sắp xếp theo tiêu chí nào đó
    data.sort(key=lambda x: x.criteria)
    
    # Bước 2: Chọn lựa greedy
    result = []
    for item in data:
        if can_add(item, result):
            result.append(item)
    
    return result
```

## 1) Problem: MaxNonoverlappingSegments

### Description
Cho N đoạn thẳng trên đường thẳng, mỗi đoạn i có:
- Điểm đầu: `A[i]`
- Điểm cuối: `B[i]` (với A[i] ≤ B[i])

**Yêu cầu:** Tìm số lượng **tối đa** các đoạn **không giao nhau**.

Hai đoạn giao nhau nếu: `max(A[i], A[j]) ≤ min(B[i], B[j])`

### Tư duy giải

**Key Insight - Greedy với sắp xếp:**
- **Chiến lược:** Chọn đoạn kết thúc sớm nhất tại mỗi bước
- **Lý do:** Để lại nhiều "không gian" cho các đoạn sau

**Cách tiếp cận:**
1. **Sắp xếp** các đoạn theo `B[i]` tăng dần (điểm kết thúc)
2. **Greedy chọn:**
   - Chọn đoạn đầu tiên (kết thúc sớm nhất)
   - Chọn đoạn tiếp theo nếu điểm đầu của nó > điểm cuối của đoạn đã chọn
3. **Đếm** số đoạn đã chọn

**Tại sao đúng?**
- Nếu chọn đoạn kết thúc sớm hơn, ta có nhiều thời gian hơn cho các đoạn sau
- Đây là bài toán **Interval Scheduling** kinh điển

### Complexity
- Time: **O(N log N)** - sắp xếp
- Space: **O(1)** - nếu sắp xếp tại chỗ, hoặc O(N) nếu tạo mảng mới

### Ví dụ chi tiết từng bước

**A = [1, 3, 7, 9, 9], B = [5, 6, 8, 9, 10]**

**Bước 1: Sắp xếp theo B[i]**

| Index | A[i] | B[i] | Sắp xếp theo B |
|-------|------|------|----------------|
| 0     | 1    | 5    | (1, 5)         |
| 1     | 3    | 6    | (3, 6)         |
| 2     | 7    | 8    | (7, 8)         |
| 3     | 9    | 9    | (9, 9)         |
| 4     | 9    | 10   | (9, 10)        |

**Bước 2: Greedy chọn**

| Bước | Đoạn xét | Điểm cuối đã chọn | A[i] > điểm cuối? | Chọn? | Điểm cuối sau khi chọn |
|------|----------|-------------------|-------------------|-------|------------------------|
| 1    | (1, 5)   | -∞                | 1 > -∞? ✅        | ✅    | 5                      |
| 2    | (3, 6)   | 5                 | 3 > 5? ❌         | ❌    | 5                      |
| 3    | (7, 8)   | 5                 | 7 > 5? ✅         | ✅    | 8                      |
| 4    | (9, 9)   | 8                 | 9 > 8? ✅         | ✅    | 9                      |
| 5    | (9, 10)  | 9                 | 9 > 9? ❌         | ❌    | 9                      |

**Kết quả:** 3 đoạn [(1,5), (7,8), (9,9)]

**Giải thích:**
- Đoạn (1,5) kết thúc sớm nhất → chọn
- Đoạn (3,6) giao với (1,5): 3 < 5 → không chọn
- Đoạn (7,8) không giao với (1,5): 7 > 5 → chọn
- Đoạn (9,9) không giao với (7,8): 9 > 8 → chọn
- Đoạn (9,10) giao với (9,9): 9 ≤ 9 → không chọn

### Edge Cases

1. **Không có đoạn nào:** return 0
2. **Tất cả đoạn giao nhau:** return 1
3. **Không có đoạn nào giao nhau:** return N

### ✔ PHP Solution

```php
function solution($A, $B) {
    $n = count($A);
    if ($n == 0) return 0;
    if ($n == 1) return 1;
    
    // Tạo mảng các đoạn và sắp xếp theo B[i]
    $segments = [];
    for ($i = 0; $i < $n; $i++) {
        $segments[] = ['start' => $A[$i], 'end' => $B[$i]];
    }
    
    usort($segments, function($a, $b) {
        return $a['end'] - $b['end'];
    });
    
    // Greedy chọn
    $count = 1;
    $lastEnd = $segments[0]['end'];
    
    for ($i = 1; $i < $n; $i++) {
        if ($segments[$i]['start'] > $lastEnd) {
            $count++;
            $lastEnd = $segments[$i]['end'];
        }
    }
    
    return $count;
}
```

### ✔ Python Solution

```python
def solution(A, B):
    n = len(A)
    if n == 0:
        return 0
    if n == 1:
        return 1
    
    # Tạo mảng các đoạn và sắp xếp theo B[i]
    segments = [(A[i], B[i]) for i in range(n)]
    segments.sort(key=lambda x: x[1])
    
    # Greedy chọn
    count = 1
    last_end = segments[0][1]
    
    for i in range(1, n):
        if segments[i][0] > last_end:
            count += 1
            last_end = segments[i][1]
    
    return count
```

### Tips & Tricks
- ✅ **Sắp xếp theo điểm kết thúc:** Đây là chiến lược tối ưu cho interval scheduling
- ✅ **Điều kiện chọn:** `A[i] > lastEnd` (không giao nhau)
- ✅ **Chứng minh tính đúng:** Nếu có lời giải tối ưu khác, ta có thể thay thế đoạn đầu tiên bằng đoạn kết thúc sớm nhất mà không giảm số lượng
- 💡 **Insight:** Bài toán này còn gọi là "Activity Selection Problem"

## 2) Problem: TieRopes

### Description
Cho mảng `A` có N phần tử (độ dài các sợi dây) và số nguyên `K`. Có thể nối các sợi dây **liên tiếp** với nhau.

**Yêu cầu:** Tìm số lượng **tối đa** các sợi dây (sau khi nối) có độ dài **ít nhất K**.

**Ràng buộc:**
- Chỉ có thể nối các sợi dây **liên tiếp** trong mảng
- Mỗi sợi dây ban đầu chỉ được dùng **1 lần**

### Tư duy giải

**Key Insight - Greedy:**
- **Chiến lược:** Cố gắng nối các sợi dây liên tiếp cho đến khi đạt độ dài ≥ K
- Ngay khi đạt ≥ K, tách thành một sợi dây mới và tiếp tục

**Cách tiếp cận:**
1. Duyệt từ trái sang phải
2. Cộng dồn độ dài các sợi dây liên tiếp
3. Khi tổng độ dài ≥ K:
   - Tăng đếm số dây
   - Reset tổng độ dài về 0
4. Tiếp tục với các sợi dây còn lại

**Tại sao đúng?**
- Nếu đợi lâu hơn để nối thêm dây, ta có thể bỏ lỡ cơ hội tạo dây mới
- Tách ngay khi đạt ≥ K cho phép tận dụng tối đa các dây còn lại

### Complexity
- Time: **O(N)** - duyệt mảng 1 lần
- Space: **O(1)**

### Ví dụ chi tiết từng bước

**A = [1, 2, 3, 4, 1, 1, 3], K = 4**

| Bước | Dây đang xét | Tổng độ dài hiện tại | Tổng ≥ K? | Action | Số dây | Tổng sau action |
|------|--------------|---------------------|-----------|--------|--------|-----------------|
| 0    | -            | 0                   | -         | Start  | 0      | 0               |
| 1    | 1            | 1                   | ❌        | Nối    | 0      | 1               |
| 2    | 2            | 1+2 = 3             | ❌        | Nối    | 0      | 3               |
| 3    | 3            | 3+3 = 6             | ✅ 6≥4    | Tách   | 1      | 0               |
| 4    | 4            | 4                   | ✅ 4≥4    | Tách   | 2      | 0               |
| 5    | 1            | 1                   | ❌        | Nối    | 2      | 1               |
| 6    | 1            | 1+1 = 2             | ❌        | Nối    | 2      | 2               |
| 7    | 3            | 2+3 = 5             | ✅ 5≥4    | Tách   | 3      | 0               |

**Kết quả:** 3 dây
- Dây 1: [1,2,3] = 6 ≥ 4 ✅
- Dây 2: [4] = 4 ≥ 4 ✅
- Dây 3: [1,1,3] = 5 ≥ 4 ✅

**Ví dụ khác: A = [3, 1, 2], K = 3**

| Bước | Dây đang xét | Tổng | ≥ K? | Action | Số dây |
|------|--------------|------|------|--------|--------|
| 1    | 3            | 3    | ✅   | Tách   | 1      |
| 2    | 1            | 1    | ❌   | Nối    | 1      |
| 3    | 2            | 3    | ✅   | Tách   | 2      |

**Kết quả:** 2 dây
- Dây 1: [3] = 3 ≥ 3 ✅
- Dây 2: [1,2] = 3 ≥ 3 ✅

### Edge Cases

1. **Tất cả dây < K và tổng < K:** return 0
   - Ví dụ: A = [1, 1], K = 5 → return 0
2. **Mỗi dây đơn lẻ ≥ K:** return N
   - Ví dụ: A = [5, 6, 7], K = 4 → return 3
3. **Mảng rỗng:** return 0

### ✔ PHP Solution

```php
function solution($K, $A) {
    $n = count($A);
    $count = 0;
    $currentLength = 0;
    
    for ($i = 0; $i < $n; $i++) {
        $currentLength += $A[$i];
        
        if ($currentLength >= $K) {
            $count++;
            $currentLength = 0; // Reset để bắt đầu dây mới
        }
    }
    
    return $count;
}
```

### ✔ Python Solution

```python
def solution(K, A):
    count = 0
    current_length = 0
    
    for length in A:
        current_length += length
        
        if current_length >= K:
            count += 1
            current_length = 0  # Reset để bắt đầu dây mới
    
    return count
```

### Tips & Tricks
- ✅ **Greedy đơn giản:** Tách ngay khi đạt ≥ K
- ✅ **Không cần sắp xếp:** Chỉ nối các dây liên tiếp
- ✅ **Reset khi tách:** Đặt lại tổng độ dài về 0
- ⚠️ Chú ý: Chỉ có thể nối các dây liên tiếp (không thể sắp xếp lại)
- 💡 **Insight:** Đây là bài toán greedy điển hình - chọn tối ưu cục bộ (tách ngay khi đủ) dẫn đến tối ưu toàn cục

## Summary - Tóm tắt

| Problem                | Output                          | Core Idea                                    | Time      | Space |
| ---------------------- | ------------------------------- | -------------------------------------------- | --------- | ----- |
| MaxNonoverlappingSegments | Số đoạn không giao nhau tối đa | Sắp xếp theo điểm cuối, chọn greedy          | O(N log N)| O(N)  |
| TieRopes               | Số dây dài ≥ K tối đa          | Nối liên tiếp, tách ngay khi đạt ≥ K        | O(N)      | O(1)  |

### Kiến thức cốt lõi cho Brown Belt

1. **Greedy Strategy:**
   - Chọn lựa tối ưu cục bộ tại mỗi bước
   - Không quay lại (no backtracking)
   - Cần chứng minh tính đúng (greedy choice property)

2. **MaxNonoverlappingSegments:**
   - Interval Scheduling Problem
   - Sắp xếp theo điểm kết thúc tăng dần
   - Chọn đoạn kết thúc sớm nhất có thể

3. **TieRopes:**
   - Greedy đơn giản: tách ngay khi đủ điều kiện
   - Không cần sắp xếp (chỉ nối liên tiếp)
   - Reset sau mỗi lần tách

4. **Pattern nhận diện:**
   - Tối đa/tối thiểu số lượng → Có thể dùng Greedy
   - Interval/segment problems → Sắp xếp + Greedy
   - Không cần backtracking → Greedy phù hợp

5. **Khi nào Greedy đúng?**
   - ✅ Activity Selection / Interval Scheduling
   - ✅ Minimum Spanning Tree (Kruskal, Prim)
   - ✅ Shortest Path (Dijkstra với trọng số dương)
   - ❌ Coin Change (general case)
   - ❌ Knapsack (general case)

6. **Tối ưu:**
   - Thường cần sắp xếp trước: O(n log n)
   - Sau đó duyệt một lần: O(n)
   - Tổng: O(n log n)

- **Greedy:** Nhanh, đơn giản, nhưng không luôn đúng
- **DP:** Chậm hơn, phức tạp hơn, nhưng đảm bảo tối ưu
- **Quy tắc:** Nếu không chứng minh được Greedy đúng → dùng DP
